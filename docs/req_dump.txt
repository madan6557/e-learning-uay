1. Ringkasan Platform 
Platform Digital UAY pada tahap awal terdiri atas tiga aplikasi yang saling mendukung. SSO/Identity 
menyediakan akun dan akses terpadu. File Service mengelola berkas institusi secara terpusat. E-Learning 
menyediakan proses pembelajaran digital bagi admin, pengajar, dan mahasiswa. 
1.1 Tujuan 
●​
Menyediakan satu tempat resmi untuk kegiatan pembelajaran daring dan pendukung pembelajaran tatap muka. 
●​
Memudahkan pengajar menyusun materi dan aktivitas berdasarkan pertemuan. 
●​
Memudahkan mahasiswa mengetahui apa yang harus dipelajari dan dikerjakan berikutnya. 
●​
Menyederhanakan enrollment, pengumpulan tugas, kuis, penilaian, serta penyampaian pengumuman. 
●​
Menyediakan riwayat yang dapat digunakan untuk menelusuri submission dan perubahan nilai penting. 
1.2 Aplikasi dalam Cakupan-

pemulihan, dan riwayat file.

2. Aplikasi SSO / Identity 
SSO/Identity merupakan pusat akun dan akses pengguna UAY. Pengguna memakai satu akun kampus untuk 
masuk ke E-Learning dan, pada tahap berikutnya, aplikasi UAY lainnya. Pendaftaran akun publik tidak tersedia; 
akun dibuat atau diimpor oleh pihak berwenang. 
2.1 Aktor SSO 
Aktor 
Tanggung jawab 
Super Admin 
Mengelola keseluruhan pengguna, administrator, peran 
umum, dan status akun. 
Admin 
Membuat atau mengimpor akun sesuai lingkup wewenang, 
membantu reset password, dan menonaktifkan akun. 
Pengguna 
Masuk, keluar, menjaga kerahasiaan akun, mengubah 
password, dan melihat profil dasar. 
 
2.2 Aturan Bisnis SSO 
●​
Satu pengguna memiliki satu identitas utama kampus. 
●​
Akun tidak dibuat melalui pendaftaran publik. 
●​
Akun memiliki identitas unik resmi yang tidak boleh digunakan oleh pengguna lain. 
●​
Akun dapat berstatus Active atau Disabled. 
●​
Akun Disabled tidak dapat masuk ke aplikasi UAY. 
●​
Peran umum menentukan aplikasi atau fungsi yang boleh diakses, sedangkan hak khusus pembelajaran tetap 
ditentukan E-Learning. 
●​
Password sementara wajib diganti ketika pengguna pertama kali masuk atau setelah reset administratif. 
●​
Aktivitas administratif penting harus dapat ditelusuri.

3. Aplikasi File Service 
File Service merupakan pusat pengelolaan berkas yang digunakan oleh aplikasi UAY. E-Learning tidak 
menyimpan berkas secara mandiri; E-Learning hanya menghubungkan materi, tugas, submission, soal, atau 
feedback dengan file yang dikelola File Service. 
3.1 Aktor File Service 
Aktor 
Tanggung jawab 
Super Admin/Admin File 
Menetapkan kebijakan file, memantau penggunaan, 
mengelola Trash, dan menangani pemulihan. 
Aplikasi UAY 
Menggunakan file sesuai konteks serta hak pengguna yang 
sedang beraktivitas. 
Pengajar 
Mengunggah dan mengakses materi, soal, atau feedback 
sesuai class. 
Mahasiswa 
Mengunggah submission dan mengakses file pembelajaran 
yang tersedia baginya. 
 
3.2 Klasifikasi dan Aturan Bisnis 
●​
Setiap file memiliki pemilik atau sumber, nama, jenis, ukuran, waktu unggah, status, tingkat akses, dan konteks 
penggunaan. 
●​
Tingkat akses file adalah Public atau Private; default-nya Private. 
●​
File Public dapat dibuka sesuai kebutuhan publik yang disetujui. 
●​
File Private hanya dapat dibuka oleh pengguna yang memiliki hak melalui konteks aplikasi. 
●​
Submission, soal ujian, dokumen mahasiswa, dan feedback pengajar selalu Private. 
●​
Mengetahui nama atau lokasi file tidak otomatis memberikan hak akses. 
●​
File executable atau berbahaya ditolak secara default. 
●​
File ZIP diizinkan untuk kebutuhan akademik seperti pengumpulan source code. 
●​
Video panjang menggunakan layanan video eksternal; unggahan langsung hanya untuk video pendek sesuai 
batas. 
●​
File yang dihapus masuk Trash selama tujuh hari, lalu dapat dihapus permanen.

3.5 Kriteria Penerimaan File Service 
●​
Kriteria penerimaan — File valid dapat diunggah dan digunakan kembali pada konteks yang tepat. 
●​
Kriteria penerimaan — File melebihi batas, executable, atau terindikasi berbahaya ditolak. 
●​
Kriteria penerimaan — Dua file bernama sama tetap menjadi dua berkas berbeda. 
●​
Kriteria penerimaan — File Private tidak dapat dibuka oleh pengguna yang tidak berhak. 
●​
Kriteria penerimaan — File di Trash dapat dipulihkan sebelum tujuh hari. 
●​
Kriteria penerimaan — Setelah penghapusan permanen, file tidak lagi dapat dipulihkan melalui fungsi normal. 
●​
Kriteria penerimaan — Riwayat menunjukkan pelaku, tindakan, file, konteks, dan waktu penghapusan atau 
pemulihan. 
3.6 Alur Utama File 
7.​ Pengguna memilih file pada aktivitas E-Learning.

9.​ File valid disimpan dan dikaitkan dengan materi atau aktivitas terkait. 
10.​Pihak yang berhak dapat membuka atau mengunduh file. 
11.​ Jika dihapus, file masuk Trash selama tujuh hari. 
12.​Admin atau pemilik yang berwenang dapat memulihkannya sebelum masa Trash berakhir.

4. Gambaran Struktur E-Learning 
STRUKTUR UTAMA 
Course berisi satu atau lebih Course Class. Setiap class memiliki Section/Pertemuan. Di dalam pertemuan, 
pengajar menyusun Resource, Quiz, dan Assignment sebagai item yang terpisah tetapi tampil dalam satu 
urutan pembelajaran. 
 
●​
Course — mata kuliah induk. 
●​
Course Class — kelas atau rombongan belajar yang berjalan. 
●​
Section/Pertemuan — pengelompokan pembelajaran berdasarkan topik atau minggu. 
●​
Resource — materi seperti teks, gambar, dokumen, tautan, video, atau tautan pertemuan. 
●​
Quiz — aktivitas soal, attempt, jawaban, dan penilaian. 
●​
Assignment — instruksi tugas, submission, resubmission, feedback, dan penilaian.

6. Aturan Bisnis E-Learning 
●​
Course hanya dapat dibuat oleh Super Admin atau Admin Prodi/Admin. 
●​
Status course pada versi awal adalah Draft, Published atau Archived. 
●​
Akun pengguna disiapkan oleh admin atau melalui import; tidak ada pendaftaran akun publik. 
●​
Peserta ditambahkan admin/pengajar atau menggunakan enrollment key jika opsi tersebut diaktifkan. 
●​
Course Archived bersifat hanya-baca bagi mahasiswa dan tidak menerima aktivitas baru. 
●​
Nilai mahasiswa tidak terlihat sebelum dipublikasikan. 
●​
Pengguna hanya dapat melihat data yang menjadi haknya. 
●​
Waktu mulai, tenggat, dan penutupan aktivitas berlaku berdasarkan waktu resmi sistem. 
●​
Riwayat submission tidak boleh ditimpa ketika mahasiswa melakukan pengumpulan ulang. 
●​
Perubahan nilai penting dan aktivitas administratif harus dapat ditelusuri.

Menjadi Software Tester (QA):
Dari Mahasiswa ke Penjaga Mutu Sistem

Selamat datang di ruang laboratorium Pengenalan Informatika. Hari ini kita tidak hanya menjadi pemakai, tetapi menjadi Software Quality Assurance (QA) untuk platform E-Learning UAY.

🎯

Target Pembelajaran

Memahami konsep QA, eksekusi skenario uji (test case), dan cara melaporkan bug secara terstruktur.

💻

Aplikasi Sasaran

E-Learning UAY (Multi-role: Mahasiswa, Dosen, Admin Prodi, Super Admin).

🔍 Mengapa Testing Penting?

"Kalau Bisa Jalan di Laptop Saya, Berarti Beres Dong?"

Di dunia rekayasa perangkat lunak (Software Engineering), kalimat di atas adalah jebakan paling berbahaya!

🎓

Sistem Akademik Lumpuh

Bayangkan 2.000 mahasiswa login serentak jam 08:00 saat ujian akhir, lalu server crash karena session race-condition. Siapa yang dirugikan?

🛡️

Peran Software Tester

Tester adalah benteng pertahanan terakhir sebelum sebuah karya cipta perangkat lunak dinikmati oleh manusia di dunia nyata.

🧠 Mindset Perangkat Lunak

Pengembang (Developer) vs Penguji (Tester)

Mengapa pembuat kode tidak boleh menjadi satu-satunya orang yang menguji aplikasinya sendiri?

👨‍💻 Mindset Pengembang (Developer)

  • Fokus: "Bagaimana membuat fitur ini berfungsi?" (Creation mindset).
  • Asumsi: Mengira pengguna akan selalu memasukkan data yang benar, tertib, dan sopan.
  • Bias Konfirmasi: Selalu mengklik tombol yang dia tahu pasti bekerja lancar (Happy Path).

🕵️ Mindset Penguji (QA / Tester)

  • Fokus: "Bagaimana jika sistem ini saya beri input aneh?" (Destructive/Curiosity mindset).
  • Asumsi: Pengguna nyata bisa saja mengetik huruf di kolom angka, submit 10 kali cepat, atau koneksi tiba-tiba putus.
  • Tujuan: Menemukan kecacatan (defect) sekarang, sebelum pengguna asli mengalaminya!
🧪 Metode Pengujian

Happy Path vs Negative Testing (Chaos)

Dua sudut pandang wajib saat menguji aplikasi web:

☀️

1. Happy Path (Positive Testing)

Menguji alur kerja normal sesuai rencana pengembang.

  • Mahasiswa memilih kuis → Menjawab soal → Klik submit → Nilai keluar.
  • Dosen mengunggah PDF materi → Mahasiswa membaca materi.
  • Admin membuat kelas baru → Kelas muncul di daftar katalog.
⚡

2. Negative Testing & Boundary Value

Sengaja memicu kondisi tidak wajar untuk melihat ketahanan sistem.

  • Bagaimana jika mengunggah file 50 MB padahal batas 5 MB?
  • Bagaimana jika klik tombol "Kumpulkan Tugas" berkali-kali sangat cepat?
  • Bagaimana jika menekan tombol Back browser saat kuis sedang berjalan?
  • Bagaimana jika kolom nilai diisi angka -50 atau teks "Gratis"?
📋 Lembar Uji

Anatomi Sebuah Test Case yang Baik

Sebelum menguji, tester bekerja berdasarkan dokumen panduan yang disebut Test Case:

1. ID & Judul
TC-QZ-001: Pengerjaan Kuis Pilihan Tunggal

Menjelaskan fitur apa yang sedang diverifikasi secara spesifik.

2. Prasyarat
Akun Mahasiswa aktif, terdaftar di kelas IF2101, kuis berstatus PUBLISHED.

Kondisi awal yang harus dipenuhi sebelum pengujian dimulai.

3. Langkah Uji
1. Buka kuis → 2. Pilih opsi B → 3. Klik tombol Selesai kuis → 4. Konfirmasi.

Urutan aksi nyata yang harus dikerjakan satu per satu.

4. Hasil Harapan
Jawaban tersimpan, skor terhitung otomatis, dan status kuis berubah menjadi Selesai.

Tolak ukur: Apakah aplikasi lulus (PASS) atau gagal (FAIL)?

🐞 Laporan Cacat

Cara Menulis Bug Report yang Dicintai Developer

Hindari laporan tidak berguna seperti "Kak tombolnya error!". Gunakan format standar industri:

Komponen Wajib Bug Report:

  • Judul Bug: Singkat, padat, lokasi jelas.
    Contoh: [Kuis] Timer berhenti saat tab browser berpindah.
  • Severity (Tingkat Dampak): Blocker / Major / Minor / Trivial (Kosmetik).
  • Steps to Reproduce: Langkah 1, 2, 3 agar developer bisa mengulangi masalahnya.
  • Expected vs Actual: Harapan vs Kejadian nyata.
  • Bukti (Evidensi): Screenshot atau rekaman layar.

Contoh Nyata:

Judul: Unggah tugas ZIP 2MB gagal tanpa pesan error.

Langkah:
1. Buka tugas Praktikum 01 sebagai Mahasiswa.
2. Klik pilih file, pilih archive.zip.
3. Klik tombol Kumpulkan.

Ekspektasi: Muncul notifikasi "Tugas berhasil dikumpulkan".
Aktual: Halaman blank putih, muncul error HTTP 500 di tab Console (F12).
👥 Pembagian Peran Kelas

4 Tim Tester Kelas Hari Ini

Setiap mahasiswa akan memegang akun dummy dengan salah satu dari 4 peran berikut:

🎓

Mahasiswa

Menguji akses materi, interaksi checklist, pengerjaan 8 bentuk soal kuis, submit tugas, dan rekap nilai.

👩‍🏫

Dosen

Membuat pengumuman penting, memeriksa antrean kuis esai, memberi nilai tugas, dan menerbitkan gradebook.

🏢

Admin Prodi

Melihat katalog prodi Informatika, mengelola status kelas aktif/arsip, dan memeriksa batas lingkup jurusan.

⚡

Chaos / Security

Mencoba login akun nonaktif, mencoba bypass URL terlarang, menguji layout di HP (mobile responsive), dan cek F12 console.

Cara Memulai Praktik Pengujian

Ikuti langkah mudah berikut di laptop atau komputer laboratorium masing-masing:

🌐

1. Buka Web Uji

2. Pilih Akun Dummy
